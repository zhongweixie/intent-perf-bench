# 洪志达分支：任务包与实验数据

已经整理完成，无需再从旧实验目录手动选择文件。提交的是四个保留案例 C19、C21、C29、C8673；未将放弃的 C34/C38 算作成功案例。

## 提交内容

- `tasks/ipb_cuda_zhida_*/`：原始公共题目源码、实际 Fuzzy/Misleading 提示词、实验运行器、正确性和性能评分器、依赖源码、参考实现及补丁、预算与来源说明。
- `results/key_experiments/zhida/`：31 条实验终点记录的 JSON/CSV 汇总、原始状态与评测、操作轨迹和提交源码。包括诊断组、反向结果和基础设施失败记录。
- `docs/zhida_cases/`：阅读入口、打包审计、cpu4 运行验证报告、SHA256 文件清单。
- `scripts/evaluate_zhida_case.py`：四个任务统一的独立评分入口。

运行器是让模型按预算作答并记录轨迹的程序；评分器无需模型 API，会执行固定正确性检查并测量提交代码性能。这四个 CUDA/Python 包使用自己的评分入口；现有仓库的 Makefile/Slurm 旧入口不能直接替代它们。每个任务 README 有完整命令。C19/C21 历史脚本走 OpenRouter，C29 走 DeepInfra；C8673 使用已登录的本地 Codex 控制器和远端 CUDA 评分器。

## 数据解读

C19 保留两个探索性配对和最初试跑；C21 保留全部四轮，第一轮反向结果未删除，挑选后三轮属于事后子集；C29 的支持来自 v2/v3，长请求及全组 API 超时另有标签；C8673 保留两轮 Codex medium/700s 配对，不将宽预算或不同接口的旧实验算作同协议重复。正确性失败可以体现误导影响，但没有有效性能加速分。参考实现只是比较答案，不代表全局最优。

C8673 初始输入以冻结协议 SHA256 匹配的 `groundtruth/public_snapshot.zip` 为准。归档中名为 `initial_public` 的目录来自实验后的可变工作区，不能当作原版。C29 v2_pair1/M1 的归档 public 工作区有缩进错误，原样保留；该诊断组的工作区不能替代当时评测快照。原始记录没有为了让结论好看而被修正。
