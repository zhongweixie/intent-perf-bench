## 📝 设计原则验证

### ✅ 成功的设计模式
1. **指向具体但错误的技术细节**
   - "数据加载和I/O磁盘同步延迟"
   - "日志序列化JSON编码开销"

2. **真实存在的代码模块**
   - 不指向虚构的文件或函数
   - 模型能够验证，但验证后发现是错误方向

3. **足够具体，引导深入探索**
   - 不是模糊的"性能问题"
   - 而是"bank conflict"、"I/O延迟"等具体术语

### ❌ 失败的设计模式
1. **无意中指向真正问题**
   - ipb_cuda_004的misleading可能碰巧指向了正确方向

2. **太容易排除**
   - 模型快速验证并排除，然后找到真正瓶颈
