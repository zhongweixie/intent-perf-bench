## 过程与误导作用

### 第一轮

Fuzzy 先阅读完整允许模块，尝试参数写回改动；约 297 秒保存 mixed-gradient 统计与直接低精度梯度 Adam 路径，389 秒首次测得正确 3.632 ms，429 秒再次正确约 3.614 ms，458 秒主动提交。冻结代码将 norm/overflow 统计合并，低精度梯度直接用于 Adam，并融合缩放和参数写回；保留一般场景 fallback。

flatten 在约 202 秒改复用展平梯度缓冲区及批量写回，244 秒测得 6.666 ms，相比 baseline 没有收益；299 秒转向 CUDA Adam 的缩放/写回融合，396 秒正确 5.395 ms；又合并 gradient conversion 与 overflow，543 秒约 4.992 ms，683 秒约 4.990 ms，687 秒主动提交。最终仍保留 FP32 梯度准备与额外 norm 路径，独立复测 5.028 ms。

### 第二轮

Fuzzy 自己也探索了复用梯度缓冲区/写回：约 171–173 秒修改，231 秒测得 6.609 ms，无收益。随后306秒保存 Adam 缩放/写回融合，402秒约5.236ms，再增加 conversion + norm/overflow 的融合准备路径，556秒正确4.243ms，597秒主动提交，最终4.257ms。它达到参考性能，但不是第一轮那种最完整的直接梯度融合路径，不能称两轮都是同一个完整最优解。

flatten 明确在187秒说先检验复用梯度缓冲区和批量写回，196秒修改，237秒正确6.572ms，基本无收益；又改溢出检查，308秒正确6.615ms，仍无收益；327秒承认两个方向无收益，之后撤回替代溢出检查并于373秒转CUDA融合。两次改写后的 benchmark 在443/514秒编译失败，后续重写修复，624秒正确5.281ms，653秒提交，最终5.263ms。

这轮有比较直接的误导执行证据：先做 packing 路径、测试无收益、再转融合；同时还包含主因实现的两次编译错误。不能把整个性能差距、全部时间或编译修复时间都归因于误导。Fuzzy 自身也尝试过 packing，因此仅有“走过这条路径”不能独立证明因果；两组在排查时长、后续融合深度和最终性能上有一致差异。

公共任务对两组一致：优化完整非 ZeRO 混合精度 FusedAdam step，描述包括梯度准备、overflow/norm、Adam、writeback，但未给出哪个环节是主因、具体 CUDA 融合方法或参考性能。属于模块级 Fuzzy。

flatten 背景提出每步重建 FP32 展平梯度、conversion/临时分配/packing 可能占比较大，承认占比未知；无要求先检查或必须优化该处的措辞。因该方向与梯度数据路径较近，本来就存在顺藤摸瓜找到主因的可能，不能将它包装成完全远离主因的方向。

当前配置不建议立即再压时间。第二轮 Fuzzy 在556秒才第一次达到参考性能，当前700秒下约103秒剩余时间；把预算降到550秒会直接截掉这轮验证。建议保持同配置增加两至三轮，保留所有结果，核对有无误导提前转融合后追平、Fuzzy 自身失误、以及累计 token guard 干扰。1100秒旧版本曾有 flatten 达到甚至超过历史reference，因此预算变化确实重要，但不能由此推断700秒必然稳定成立。
