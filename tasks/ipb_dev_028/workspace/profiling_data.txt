    10000    0.000    0.000    0.000    0.000 {built-in method builtins.len}

The bottleneck is the nested loop:
- Outer loop: 10,000 records
- Inner loop: grows from 0 to ~7,700 unique records
- Total comparisons: ~38.5 million (O(n²) complexity)

With 150k records, estimated time would be 225x worse: ~10,000+ seconds.

Root cause: Linear search through unique_records list for each new record.
Solution: Use set to track seen IDs for O(1) lookup instead of O(n) linear search.
